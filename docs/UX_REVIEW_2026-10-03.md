# FormForge: CAD and website UX review

Audit date: October 3, 2026. Product: the current FormForge workshop, CAD editor, print/export flow, and local community showcase. Audience assumption: hobbyists and makers designing functional parts for FDM printing, including people new to CAD.

## Verdict before this work

**Overall: 6.5/10. CAD workflow: 5.5/10.** This is an expert heuristic rating, not a user-survey score. The interface looks approachable and the core geometry engine works, but behavior is not yet consistent enough to earn everyday trust. A printable-part tool must make exact dimensions, safe camera navigation, recoverable editing, and reliable export its strongest features.

| Area | Before | Why |
| --- | ---: | --- |
| Visual identity and hierarchy | 7.5 | Consistent style and actual previews; weak secondary contrast and excessive introductory space. |
| Starting and finding projects | 7.0 | Clear New/Import/Continue, search, and sorting; backups and collections need better recovery and mobile paths. |
| CAD precision and predictability | 5.5 | Dimensions below the fold; unstable numeric editing, selection/tool conflicts, incomplete multi-selection behavior. |
| Editing safety and recovery | 5.0 | Camera gestures can edit; Lock is inconsistent; checkpoint restore has no recovery snapshot. |
| Print/export confidence | 5.5 | Real geometry checks, but stale results and ambiguous wall/print-readiness claims; GLB unit/axis mismatch. |
| Accessibility and mobile | 6.0 | Labeled controls and responsive panels; small text, faint labels, overlay collisions, and inconsistent dialogs. |
| Discovery and trust | 6.5 | Sample content is labeled; empty states, local-save failures, and update behavior need work. |

The goal is a workflow that meets a 9/10 usability standard for its supported browser-CAD scope. A rating cannot establish demand from thousands of users. Preference, retention, successful physical prints, and large-scale reliability require testing with real makers and actual slicers/printers.

## Current-run evidence and task steps

These screenshots were captured and inspected in this review. Earlier redesign screenshots were not reused as audit evidence.

1. **Find and resume a project — mostly healthy.** Real previews and clear entry actions work. The large welcome section and faint supporting text delay the actual project library. [Workshop](ux-review-2026-10-03/01-workshop-before.png).
2. **Orient in the design center — mixed.** The canvas is prominent, but camera commands, selection state, and editing modes need more predictable behavior. [CAD overview](ux-review-2026-10-03/02-cad-before.png).
3. **Select and enter exact dimensions — poor.** At 1280×800, the shape list and lengthy boolean explanation push the first position and size fields below the visible editing area. [Selected properties](ux-review-2026-10-03/03-properties-before.png).
4. **Check whether the model is ready — misleading.** The light-theme print heading has inadequate contrast, “Min wall” is a configured target rather than a measured minimum, and the code can display stale analysis. [Print panel](ux-review-2026-10-03/04-print-before.png).
5. **Export — promising but incomplete.** Format explanations are useful, but the handoff asks the user to leave and check another tab; evaluation errors can look like endless rebuilding. [Export](ux-review-2026-10-03/05-export-before.png).
6. **Use the canvas on a phone — mixed.** Framing works, but navigation controls wrap and compete with several floating action groups. [Phone CAD](ux-review-2026-10-03/06-mobile-cad-before.png).
7. **Open phone modeling tools — obstructed.** The floating switcher overlaps panel content; starting placement should immediately return the user to the canvas. [Phone tools](ux-review-2026-10-03/07-mobile-tools-before.png).
8. **Find inspiration — too much introductory UI.** Multiple navigation rows and a tall hero delay actual models on a phone. [Phone community](ux-review-2026-10-03/08-mobile-community-before.png).

## Findings and recommended fixes

“Observed” means verified in the current UI or screenshot. “Code” means a concrete source path was inspected; interaction regressions need tests and browser verification before closure.

| ID | Priority | Finding / pain point | Recommendation | Evidence |
| --- | --- | --- | --- | --- |
| CAD-01 | P1 | Right/middle pointer-down can enter move, placement, or sculpt code even though right-drag is described as pan. | Restrict modeling mutations to the primary pointer and preserve camera gestures. | Code: Viewport pointer handling. |
| CAD-02 | P1 | Mirroring creates negative scale but gizmo commits clamp it to positive 0.05. Rotating a mirrored part can collapse it. | Preserve signed nonzero scale and test Mirror → Rotate → Undo. | Code: editor mirror and viewport gizmo commit. |
| CAD-03 | P1 | Lock only guards some interaction paths. Inspector, gizmo, sculpt, align, and delete can bypass it. | Enforce locks centrally and explain disabled controls. | Code: store mutation paths and inspector. |
| CAD-04 | P1 | Every numeric keystroke changes geometry and history; intermediate empty/negative values are invalidated. | Draft numbers locally, validate, commit on Enter/blur, revert on Escape; one undo per edit. | Code: numeric inputs. |
| CAD-05 | P1 | Switching tools or Undo can leave a stale pending-placement ID. | Use one placement cancellation path and reconcile history/tool changes. | Code: editor placement and history. |
| CAD-06 | P2 | A multi-selection highlights several objects but transformation, nudging, and framing target only one. | Apply an atomic shared transform and frame selected bounds. | Code: store, viewport, App shortcuts. |
| CAD-07 | P2 | Selecting an object silently switches Rotate/Scale/Select to Move. | Preserve the chosen tool during selection changes. | Observed selection; code: selectNode. |
| CAD-08 | P2 | Dimensions are not immediately visible; rotation and scale are hidden in Simple mode. | Put Size first, then Position/Rotation/Scale in both modes; progressively disclose advanced controls. | Step 3 and Inspector/styles. |
| CAD-09 | P2 | Drop to plate uses nominal height and omits imported meshes. | Use transformed world bounds for all selected unlocked objects. | Code: Inspector drop action and modelGeometry. |
| CAD-10 | P2 | Subtract’s “first” object follows document order rather than visible selection order. | Use a consistent base and name it before subtraction. | Code: combineSelected and selection UI. |
| CAD-11 | P2 | Camera dropdown cannot reapply its already-selected view; “Free” snap leaves rotation/scaling snaps active. | Make views repeatable commands and expose tool-specific snapping. | Code: ViewportTools and transform configuration. |
| CAD-12 | P2 | Volume sculpt help/settings advertise modifiers that are not all honored. | Implement supported symmetry/invert behavior or scope the visible options truthfully. | Code: help, volume stamp, brush settings. |
| CAD-13 | P2 | Selected rows expand and move neighboring items; advanced controls use very small typography. | Stable row actions, compact model list, readable fields and touch targets. | Step 3 and component CSS. |
| CAD-14 | P2 | Mobile tool overlays cover actions and remain open during placement. | Give panels a consistent close action, clear the canvas during placement, remove collisions. | Steps 6–7. |
| CAD-15 | P2 | Selection management and print review are difficult to discover through keyboard commands. | Add Select all, Clear selection, Fit selection, and Print checks commands. | Current command list. |
| PRINT-01 | P1 | GLB import/export ignores glTF meters/Y-up versus FormForge millimeters/Z-up. | Apply inverse transforms and test asymmetric physical dimensions. | Code: importers/exporters; Khronos specification. |
| PRINT-02 | P2 | Print panel can show old “Ready” analysis during rebuilding or errors. | Share a freshness-aware state model between panel, status, and export. | Code: PrintPanel versus TopBar. |
| PRINT-03 | P2 | “Min wall” and “Ready to print” overstate the available analysis. | Label wall target, expose printer dimensions, distinguish basic geometry checks from slicer/physical validation. | Step 4 and analysis.ts. |
| PRINT-04 | P2 | Export failure can be described as rebuilding forever. | Prioritize errors, offer retry and editable backup, keep a direct print-review path. | Code: TopBar export condition. |
| PRINT-05 | P2 | Ordinary multi-file GLTF is advertised but companion resources are not imported. | Support companions or constrain the picker/copy to self-contained supported files. | Code: file picker and importGlbData. |
| SAVE-01 | P1 | Failed save is swallowed, so a later project load can overwrite unsaved in-memory edits. | Return an explicit save outcome; block replacement on failure and offer retry/backup. | Code: saveNow and App navigation. |
| SAVE-02 | P1 | Restoring a checkpoint overwrites the project and clears undo without retaining the latest work. | Save a recovery checkpoint first and stop if that fails. | Code: History restore. |
| SAVE-03 | P2 | Asynchronous checkpoint loading can display the previous project’s results. | Clear/guard requests by project identity and expose loading/error/retry. | Code: History loading effect. |
| SITE-01 | P2 | Supporting text is faint: subtle light text is about 3.16:1 on white, 2.92:1 on ivory. | Darken light tokens and raise dark-theme secondary contrast. | Step 1 plus computed source colors. |
| SITE-02 | P2 | Returning users repeatedly see a large introductory hero. | Compact the returning-user header and prioritize their models. | Step 1. |
| SITE-03 | P2 | “Update local showcase” actually creates another entry. | Upsert by source project identity. | Code: project action and local publication. |
| SITE-04 | P2 | Saved-looking reactions/collections can fail to persist; comments disappear on reload. | Persist before confirming success, report errors, and retain local comments. | Code: Community localStorage and state. |
| SITE-05 | P2 | Empty community filters show a blank grid with no recovery. | Result count, empty explanation, and clear-filter actions. | Code: filtered grid rendering. |
| SITE-06 | P2 | Mobile community navigation and hero hide the actual models. | Reduce duplicate navigation and compact mobile introduction. | Step 8. |
| SITE-07 | P3 | Showcase dialog focus differs from native dialogs; detail view does not follow Back/reload. | Reuse native dialog and route detail/search/filter state. | Code: Community modal and navigation. |
| SITE-08 | P3 | Mobile collection removal is inaccessible. | Add a compact manage/remove action that preserves contained projects. | Code: responsive collection controls. |
| SITE-09 | P2 | The generator looks like general AI chat even though text creation is local template matching. | Explain supported recipes, local processing, and optional unavailable services without promising arbitrary AI designs. | Code: GenerateStudio and promptToParametricNodes. |
| RELEASE-01 | P1 | No GitHub validation workflow or Sites release setup exists. | Validate every pushed commit; review PR, merge green build, publish matching source/artifact. | Repository configuration. |

## Implementation and verification plan

1. Preserve the previous redesign in a feature-branch checkpoint and add CI (completed; baseline 66 tests, typecheck/build passed).
2. Repair CAD selection, transforms, locks, placement and numeric input with regression tests.
3. Reorganize precise editing and improve mobile/keyboard controls without replacing the geometry engine.
4. Fix exchange coordinates, current print feedback, recovery and project replacement.
5. Improve discovery, persistence feedback, contrast and local-showcase navigation.
6. Repeat the audited journeys, capture after screenshots, run full checks and review the diff.
7. Push each commit, verify CI, create and merge a PR, then publish the validated revision to the public FormForge Site.

## Sources and limits

- [glTF 2.0 coordinate and unit specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html): unit/axis interoperability.
- [Shapr3D export](https://support.shapr3d.com/hc/en-us/articles/7874524196764-Export): explicit format, units and export controls.
- [Shapr3D project versions](https://support.shapr3d.com/hc/en-us/articles/16074344685468-Project-Versions): recoverable version workflow.
- [Prusa first-print workflow](https://help.prusa3d.com/article/first-print-with-prusaslicer-3-0-0_1079761): profiles and sliced-layer inspection beyond geometry checks.

Comparators inform the recommendations; they do not prove that FormForge’s implementation works. Screenshots do not establish full WCAG compliance. This review includes source inspection, automated regressions and browser tasks; it does not include moderated studies, physical printing, or thousands-user load/retention evidence. The local showcase remains browser-local; publishing the application does not create a public model-sharing backend.

## Final result

All 33 scoped recommendations above have implementation changes. Five additional issues found in independent review were repaired before release: overlapping imports during saving, nonuniform scaling of differently rotated groups, capsule preview/export disagreement, numeric normalization display, and volume sculpt bypassing locks. A follow-up regression also prevents conversion from clearing existing volume strokes while another shape is locked.

### Repeated eight-step journey

1. **Workshop — healthy.** Compact returning-user layout, stronger contrast, direct continue/import/new actions. Project management retains the previous workflow. [After](ux-review-2026-10-03/09-workshop-after.png).
2. **Enter CAD — healthy.** Clear Build/Sculpt grouping and readable transform tools. The production preview successfully restored an existing project and evaluated its geometry. [After](ux-review-2026-10-03/10-cad-after.png).
3. **Precise edit — healthy with explicit limits.** Width/depth/height are immediately accessible. Rotated shapes explain local-axis dimensions; Print shows overall world size. Group transforms are atomic. Differently rotated groups scale uniformly to avoid invalid shear. [After](ux-review-2026-10-03/10-cad-after.png).
4. **Print review — healthy.** Basic checks use only the current model. A 48 mm-wide model changed to “Review before slicing” after setting a 30 mm build width. Local wall thickness, bed contact and supports are explicitly left to the slicer. [After](ux-review-2026-10-03/11-print-after.png).
5. **Export — improved, native download completion unverified.** Format choice includes current dimensions and direct access to Print. Binary GLB round-trip tests prove unit/orientation handling; existing 3MF/STL tests verify serializers. The in-app browser showed the download-request feedback but the automation download event timed out; this review does not claim that a local file completed downloading. [After](ux-review-2026-10-03/12-export-after.png).
6. **Phone CAD — healthy layout.** At 390×844 the camera/snap/display controls fit on one row and the canvas has clear bottom controls. [After](ux-review-2026-10-03/13-mobile-cad-after.png).
7. **Phone panels — healthy layout.** Panels end above the switcher/close controls; a scrim prevents accidental canvas edits underneath. Placement exposes a touch Cancel action. [After](ux-review-2026-10-03/14-mobile-inspector-after.png).
8. **Discovery — healthy within local-showcase scope.** Models appear much earlier on mobile. No-result search displays recovery actions; detail URLs survive reload and return to discovery. [After](ux-review-2026-10-03/16-mobile-community-after.png).

### Acceptance evidence

- Fresh full validation: **40 model tests + 88 web tests = 128 passing**, all type checks and the production build pass.
- Independent review verified closure of its findings with 59 targeted passing tests. A subsequent defensive lock regression also passes the full suite.
- Browser: created a separate calibration project; entered 40×24×12 mm; Escape reverted a draft of 99 back to 40; Drop to plate set center Z to 6; Rotate stayed selected with a 45° snap; locking disabled edit fields.
- Browser: selected two parts, nudged both by 1 mm (X values 0→1 and 8→9), and one Undo restored the movement.
- Browser: created and restored a checkpoint and verified the additional “Before restore” recovery checkpoint appeared.
- Browser: checked light/dark CAD, 390×844 CAD/panels/generator/community, search empty state, detail reload and back navigation.
- Production preview at port 4173 restored an existing project, rendered the real mesh and displayed current dimensions/checks. Earlier development hot-reload errors from concurrent editing are not production failures.
- Current-run screenshots include [history recovery](ux-review-2026-10-03/17-history-after.png), [dark CAD](ux-review-2026-10-03/18-dark-cad-after.png), and [honest local generator](ux-review-2026-10-03/15-mobile-generator-after.png).
- GitHub validates every pushed commit and every pull request. The archived public output is the root `dist/`; Sites is configured to publish that same build from the validated merged source.

### Remaining product work and evidence needed

1. Run task-based sessions with beginner and experienced makers: create a bracket, import and resize a mesh, recover a mistake, and export to a slicer. Measure completion, errors, time and confidence before treating “9/10” as a user-validated result.
2. Verify native file downloads in supported full browsers, then open exports in actual slicers and perform representative physical prints. This automated environment did not complete a native download handoff.
3. Test touch interaction on actual phones/tablets and a keyboard/screen-reader accessibility matrix. Responsive screenshots alone do not certify accessibility.
4. Add authenticated sync, public model storage, moderation and abuse controls if the local showcase is to become a real shared community. Publishing this application does not supply those services.
5. Benchmark large imported meshes and low-end devices. The production bundle still contains substantial geometry code; its size warning remains visible rather than being suppressed.

These are meaningful follow-up validation and product tracks. They are not claims that a public deployment has already proven demand, physical print success, or operation at thousands-user scale.
